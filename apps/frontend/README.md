# Нечто — Frontend

Telegram Mini App для игры «Нечто». React + TypeScript + Vite.

## Требования

- Node.js 20+
- npm

## Установка

```bash
cd apps/frontend
npm install
```

## Настройка окружения

Скопируйте файл с примером переменных окружения и при необходимости укажите адрес API:

```bash
cp .env.example .env
```

| Переменная     | Назначение                         | По умолчанию            |
| -------------- | ----------------------------------- | ------------------------ |
| `VITE_API_URL` | Адрес backend API (Java)            | `http://localhost:8080` |

## Запуск в режиме разработки

```bash
npm run dev
```

Приложение будет доступно по адресу, который выведет Vite (обычно `http://localhost:5173`).

## Проверка внутри Telegram

Приложение требует реальный Telegram-контекст: без данных `window.Telegram.WebApp.initDataUnsafe.user`
(идентификатор пользователя) показывается экран-заглушка, а не главный экран — создание и
подключение к комнате не работают без них, так как backend требует `X-Telegram-Id` в каждом запросе.
Для локальной проверки используйте туннель (например, ngrok) и укажите полученный HTTPS-адрес
в настройках бота у [@BotFather](https://t.me/BotFather) (`/setmenubutton` или `/newapp`).

## Сборка

```bash
npm run build
```

Собранные файлы появятся в каталоге `dist`.

## Линтинг

```bash
npm run lint
```

## Тесты

```bash
npm run test
```

Unit- и компонентные тесты (Vitest + Testing Library) покрывают API-клиент, редьюсер
WebSocket-событий и ключевые сценарии экранов (валидация, загрузка, ошибки), поскольку
полный сценарий проверяется только внутри реального Telegram-клиента.

## Статус

- **FE-1**: стартовый экран (заголовок «Нечто», действия «Создать комнату» / «Присоединиться»).
- **FE-2**: сценарий от создания комнаты до ожидания участников — форма создания с выбором
  количества игроков (4–12), подключение по коду, экран лобби с живым списком участников
  (REST + WebSocket по контракту из [`docs/API.md`](../../docs/API.md)), копирование кода
  комнаты, состояния загрузки/ошибки.
