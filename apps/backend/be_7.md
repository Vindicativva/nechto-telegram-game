### Описание

Реализовать серверный сценарий запуска игровой партии: связать модуль лобби с фабрикой колоды (DeckFactory), выполнить случайную рассадку игроков за столом, раздать по 4 карты на руки, определить начальные роли («Нечто» и «Человек») и настроить раздельную отправку публичного и приватного состояния по WebSocket.   

### Требования

Реализовать сервис GameStartService:

- [x] Фиксация списка участников, случайное перемешивание порядка мест за столом и установка направления хода по часовой стрелке;   
- [x] Вызов DeckFactory для формирования стартовых рук (по 4 карты каждому) и общей колоды добора;   
- [x] Автоматическое назначение ролей по п. 4.2.4 ТЗ: игрок, получивший карту «Нечто», получает роль THE_THING, остальные участники — роль HUMAN; Перевод комнаты в статус IN_PROGRESS (IN_GAME) с запретом подключения новых участников и изменения колоды.   

Реализовать фильтрацию исходящих данных (п. 4.1.5 и п. 4.2.11):

- [x] Отправка публичного GAME_STATE в топик комнаты без карт и ролей;   
- [x] Персональная отправка PLAYER_PRIVATE_STATE каждому игроку в его личную очередь /user/queue/game.   

Написать модульные и интеграционные тесты (JUnit 5):

- [x] Проверка, что при старте партии на $N$ игроков ровно один участник получает роль THE_THING и карту «Нечто», а остальные $N - 1$ — роль HUMAN;   
- [x] Проверка безопасности: в публичном сообщении GAME_STATE отсутствуют поля ролей и идентификаторы карт на руках игроков;   
- [x] Проверка блокировки повторного запуска уже начатой игры.   

### Критерии приёмки

- [x] При запуске партии каждому игроку на сервере назначается корректная роль и ровно 4 карты на руку.   
- [x] Публичные WebSocket-сообщения не содержат скрытой информации о ролях и картах участников (п. 4.2.11).   
- [x] Все модульные и интеграционные тесты запускаются через Maven и проходят в CI-пайплайне GitHub Actions.
