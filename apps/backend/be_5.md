# Реализация синхронизации лобби в реальном времени

## Описание
Реализовать синхронизацию лобби в реальном времени через **Spring WebSocket/STOMP**, обработку подключения и выхода участников, управление составом лобби и передачу прав создателя при отключении.

## Требования
- [x] Настроить брокер сообщений WebSocket (эндпоинт `/ws-game`, рассылка в топик комнаты `/topic/room/{code}`).
- [x] Реализовать обработчик `@MessageMapping("/room/{code}/join")` с проверками:
  - комната не заполнена (`ROOM_FULL`);
  - игра не начата (`ROOM_ALREADY_STARTED`);
  - Telegram ID не дублируется (п. 4.2.1, идемпотентное переподключение).
- [x] Реализовать рассылку события `ROOM_STATE` всем подключённым клиентам при изменении состава комнаты.
- [x] Реализовать передачу прав создателя участнику с самым ранним временем подключения при явном выходе текущего хоста.
- [x] Обработать `SessionDisconnectEvent`: удержание прав создателя в течение **5 минут** при сетевом сбое до передачи следующему игроку (п. 4.2.1).
- [x] Реализовать команду запуска игры с серверной проверкой диапазона участников (**от 4 до 12 человек**).
- [x] Добавить тесты на многопользовательские сценарии и краевые случаи лобби.

## Критерии приёмки
- [x] Обработка WebSocket-сообщений выполняется потокобезопасно.
- [x] Попытки несанкционированного входа (превышение лимита, неверный код, повторный вход) отклоняются с понятными кодами ошибок.
- [x] Смена создателя комнаты и таймаут 5 минут работают строго по спецификации ТЗ 4.2.1.
- [x] Интеграционные тесты стабильно проходят в пайплайне сборки.
