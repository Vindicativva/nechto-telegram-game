# Реализация доменной модели и базового API игровых комнат

## Описание
Подготовить доменную модель сущностей комнаты и игрока, реализовать потокобезопасное хранение активных лобби в оперативной памяти сервера, унифицировать ответы об ошибках и реализовать базовые HTTP-эндпоинты.

## Требования
- [x] Создать доменные классы:
  - `Player` (`id`, `telegramId`, `username`, `isHost`, `connectedAt`)
  - `Room` (`code`, `name`, `maxPlayers`, `players`, `status`)
- [x] Реализовать генератор уникальных 6-значных буквенно-цифровых кодов комнат с проверкой на коллизии.
- [x] Реализовать потокобезопасный in-memory репозиторий комнат на базе `ConcurrentHashMap`.
- [x] Реализовать контроллер `POST /api/rooms` с серверной валидацией имени (`1–32` символа) и вместимости (`4–12` человек).
- [x] Реализовать контроллер `GET /api/rooms/{code}` для проверки существования и доступности комнаты.
- [x] Настроить глобальный обработчик ошибок (`@ControllerAdvice`) с унифицированным форматом сообщений.
- [x] Добавить unit-тесты сервисов и интеграционные тесты для HTTP-эндпоинтов.

## Критерии приёмки
- [x] Основные позитивные и негативные сценарии создания комнаты покрыты тестами.
- [x] Тесты запускаются одной стандартной командой Maven (`mvn test`).
- [x] Ошибки API имеют предсказуемый и унифицированный формат.
- [x] Документация эндпоинтов позволяет FE-разработчику подключиться без изучения исходного кода сервера.
- [x] CI в GitHub Actions корректно выполняет сборку бэкенда и прогон тестов.
